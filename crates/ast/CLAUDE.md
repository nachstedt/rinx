# Notes on `rinx_ast`

The AST is what a build phase reads back from a `.ast` file, so everything here must survive a serde round trip unchanged (`tests/integration/ast_round_trip.rs` checks this over `examples/` and `docs/`).

- **`SourceMap` stays beside the `Document`, never in it**, and has no serde impl on purpose: where each block, name and construct was written changes when lines move, and must not enter the cache key. The document points into it through typed handles (`Named<T>`'s `NameId`, a block's `BlockId`), minted only by `SourceMap`. A test refuses any `serde(skip)` in the crate.
- A span that *does* stay in the document is one a later phase reports at (an inline reference's, a toctree entry's). `Span` carries an optional `FileId` so a diagnostic from an `.. include::`d fragment names the fragment.
- `DiagnosticCode` is generated by one macro from a single table (enum, `as_str`, `FromStr`, `ALL`, docs from each variant's doc comment), because `.. noqa:` needs the two directions to be exact inverses. Regenerate `docs/diagnostics.rst` after changing it.
- Reporting vocabulary (`Diagnostic`, `DiagnosticSubject`, `Suppression`) lives here because every phase produces and forwards it. Severity decisions key on `DiagnosticSubject`, never on the message text.
- `AssetUri::resolve` is the one place an image or `:download:` path is resolved, so the bundler, the validator and the renderer agree.
